# §5.3  CLOS — Common Lisp Object System

**Scope:** TorCL's CLOS covering class representation, instance layout,
generic function dispatch, method combination, `make-instance` protocol,
and class redefinition.  Targets full ANSI CLOS (chapters 4 & 7).  Full
AMOP deferred to v2 (§0.2) but internals anticipate it — all MOP
extension points exist as generic functions with default methods.

Cross-references: object model §1, compiler §4, GC §3, runtime §2.

---

## 5.3.2  Data Structures

### D5.03 — Class Metaobject Layout

Every class is a heap-allocated standard object whose class is a metaclass.

```text
Offset  Field                     Type               Notes
──────  ────────────────────────  ─────────────────  ──────────────────────
  0     header                    ObjectHeader       tag = HeapObject (§1)
  8     metaclass-stamp           u32                stamp of the metaclass
 12     pad                       u32                alignment
 16     name                      TorclVal (symbol)
 24     direct-superclasses       TorclVal (list)
 32     class-precedence-list     TorclVal (simple-vector)   cached CPL
 40     direct-slots              TorclVal (list)            slot-definition objects
 48     effective-slots           TorclVal (simple-vector)   effective-slot-defs
 56     direct-default-initargs   TorclVal (list)
 64     class-stamp               u64                monotonic, see §5.3.4
 72     instance-slot-count       u32
 76     flags                     u32                finalized? abstract? redefined?
 80     prototype                 TorclVal           prototype instance or NIL
 88     class-slots-alist         TorclVal (alist)   (name . value) for :class alloc
 96     wrapper                   *ClassWrapper      → current wrapper (D5.04)
```

Total: 104 bytes (13 words), fitting one cache line pair.

### D5.04 — ClassWrapper

Lightweight, immutable descriptor shared between class and instances.
On class redefinition a **new** wrapper is allocated; the old wrapper's
`state` is set to `:obsolete`, enabling the stamp-check fast path
(§5.3.10) without touching the class metaobject.

```text
Offset  Field            Type          Notes
──────  ──────────────  ────────────  ──────────────────────
  0     stamp           u64           copy of class-stamp at creation
  8     state           Atomic<u8>    :current (0) | :obsolete (1)
  9     pad             [u8;7]
 16     class-ref       *Class        back-pointer to class metaobject
 24     slot-layout     *[SlotInfo]   (name, index, initform) triples
 32     slot-count      u32
```

### D5.05 — Slot-Definition Objects

```lisp
(defclass direct-slot-definition ()
  ((name :type symbol) (initform :type (or function null))
   (initfunction :type (or function null)) (initargs :type list)
   (type :type type-specifier)
   (allocation :type (member :instance :class))
   (readers :type list) (writers :type list)))

(defclass effective-slot-definition (direct-slot-definition)
  ((location :type (or fixnum cons))))
  ;; fixnum = instance slot index; cons = (:class . cell) for class slots
```

### D5.06 — Generic Function Metaobject

```text
Offset  Field                   Type                  Notes
──────  ──────────────────────  ────────────────────  ──────────
  0     header                  ObjectHeader          tag = Function
  8     name                    TorclVal (symbol)
 16     lambda-list             TorclVal (list)
 24     methods                 TorclVal (list)       method metaobjects
 32     method-combination      TorclVal
 40     argument-precedence     TorclVal (list)       APO for dispatch
 48     discriminating-function TorclVal (function)   compiled entry point
 56     method-table            *MethodTable          D5.07
 64     dispatch-cache          *DispatchCache        D5.08
 72     gf-stamp                u64                   inc on method change
 80     min-args/max-args       u16/u16               0xFFFF = &rest
 84     flags                   u32                   sealed? single-dispatch?
```

### D5.07 — MethodTable

Flat sorted vector of `(specializer-tuple, method-object)` pairs.
For single-dispatch GFs the tuple degenerates to one entry.

```rust
struct MethodTable {
    entries: Vec<MethodEntry>,
    eql_entries: Vec<EqlMethodEntry>,  // kept separate for eql specializers
}
struct MethodEntry {
    specializers: Box<[SpecializerRef]>,
    qualifiers:   Box<[Symbol]>,
    method:       TorclVal,
    fast_function: TorclVal,           // unwrapped for direct call
}
```

### D5.08 — Dispatch Cache

Hash-based polymorphic cache mapping class-stamp tuples → effective methods.

```rust
struct DispatchCache {
    entries: Box<[CacheEntry]>,     // power-of-2 sized
    mask: usize,
    generation: u64,                // must match gf-stamp; stale → miss
}
struct CacheEntry {
    stamps: [u64; MAX_DISPATCH_ARGS],  // MAX_DISPATCH_ARGS = 8
    effective_method: TorclVal,
}
```

GFs with > 8 dispatched args fall back to full method-table search (R5.74).

## 5.3.3  Algorithm A5.01 — C3 Linearization

Standard C3 algorithm (Barrett et al. 1996), mandated by ANSI CL.

```text
function C3-LINEARIZE(class):
    if class has no direct superclasses: return [class]
    inputs ← [C3-LINEARIZE(s) for s in direct-superclasses(class)]
    append direct-superclasses(class) as final input
    result ← [class]
    loop:
        candidates ← {head(L) for non-empty L in inputs}
        if empty: return result
        select first c in candidates not in tail of any input list
        if none: signal ERROR "inconsistent CPL for ~A" class
        append c to result; remove c from heads of all input lists
```

The CPL is computed once at class finalization and cached in D5.03 offset 32.
Class redefinition invalidates and recomputes (R5.67).

## 5.3.4  Instance Layout & Stamps

### Instance memory layout (D5.09)

```text
┌────────────────────┐  offset 0    ObjectHeader (8 bytes)
├────────────────────┤  offset 8    wrapper pointer → ClassWrapper
├────────────────────┤  offset 16   slot[0] .. slot[N-1] (8 bytes each)
└────────────────────┘  size = 16 + 8N bytes (R5.68, R5.69)
```

### Stamp protocol

Each class gets a monotonically increasing **class stamp** (u64) from a
global atomic counter, copied into its `ClassWrapper`.

- **Fresh instance:** wrapper → current ClassWrapper, state = `:current`.
- **Redefinition:** new ClassWrapper allocated, old state → `:obsolete`.
- **Fast path:** load `instance.wrapper.state`; if `:current` proceed,
  if `:obsolete` call `update-instance-for-redefined-class` (§5.3.10).

Analogous to HotSpot's klass pointer — one indirection resolves class identity.

## 5.3.5  Slot-Value Protocol

### `slot-value` / `(setf slot-value)` (R5.70)

Both dispatch through `slot-value-using-class` / `(setf slot-value-using-class)`.
The default method on `standard-class` reads the slot location from the
effective-slot-definition: `fixnum` → instance slot via `%instance-ref`
(offset `16 + 8*index`); `cons` → class-allocated slot via `(cdr cell)`.
If the value is `+slot-unbound+`, calls `slot-unbound` (R5.71).

### `slot-boundp` (R5.86)

Dispatches through `slot-boundp-using-class`; returns `(not (eq val +slot-unbound+))`.

### `slot-unbound` / `slot-missing` (R5.71, R5.72)

Default methods signal `unbound-slot` and `simple-error` respectively.
Both are generic functions users may specialize for custom behavior.

## 5.3.6  Generic Function Internals

### Discriminating function compilation (R5.75)

On method-set change the runtime: (1) increments `gf-stamp`, (2) invalidates
dispatch cache, (3) compiles a new discriminating function.

| Method count | Strategy |
|--------------|----------|
| 0 | `no-applicable-method` trampoline |
| 1 | Direct call to sole method (after type check) |
| 2–4 | Linear type-test sequence |
| 5+ single-dispatch | Vtable dispatch (A5.02) |
| 5+ multi-dispatch | Cache probe → miss handler (A5.03) |

### eql-specializer handling (R5.76)

`eql` specializers are checked **before** class-based dispatch.  Each
compiles to an `eq` (or `eql` for numbers/characters) test at the top
of the discriminating function, ordered by argument position.

## 5.3.7  Algorithm A5.02 — Single-Dispatch Vtable

For GFs dispatching on one argument (the common case): a per-GF
class-indexed vtable.

```text
Lookup:
  stamp ← wrapper(arg).stamp
  em ← gf.vtable[stamp & vtable-mask]
  if em.stamp == stamp: call em.function
  else: miss → method-table search, populate vtable entry
```

Power-of-2 open-addressed hash, linear probing (max 4).  Resize at 75% load.
**Target:** vtable hit ≈ 2 loads + indirect call ≈ 3–5 ns (R5.90).

---

## 5.3.8  Algorithm A5.03 — Multi-Dispatch Cache

For GFs dispatching on ≥ 2 arguments:

```text
function CACHE-LOOKUP(gf, args[0..n]):
    cache ← gf.dispatch-cache
    if cache.generation ≠ gf.gf-stamp: goto MISS
    hash ← XOR(rotate-left(stamp-of(args[i]), i*7) for i in 0..n)
    index ← hash & cache.mask
    ;; probe at index, then linear +1..+3
    if entry.stamps[0..n] match: return entry.effective_method
    MISS: compute-effective-method, install in cache, return
```

**Sizing:** initial 16, grows to `max(64, 2*method-count)`, max 4096.

### Cache invalidation (R5.85)

1. Acquire per-GF spinlock (write side).
2. Bump `gf-stamp` (also serves as generation).
3. Release lock.
4. Readers see generation mismatch → miss → recompute.

Generation-check makes invalidation **non-blocking** for readers.

## 5.3.9  Method Combination

### Standard method combination (R5.77)

```text
1. Most-specific :around → call-next-method →
   2. All :before methods (most-specific-first)
   3. Primary methods (most→least specific, via call-next-method)
   4. All :after methods (least-specific-first)
   Return value from primary chain.
```

`call-next-method` is a closure over the remaining method chain.
If no next method exists, calls `no-next-method`.

### Short-form `define-method-combination` (R5.78)

The combination name doubles as the operator symbol.
Effective method = `(name (call-method m1) (call-method m2) ...)`.
Example: `(define-method-combination progn :identity-with-one-argument t)`.
(The `:identity-with-one-argument` option, when true, optimizes the
single-method case to return its value directly without wrapping in the
operator form.)

### Long-form `define-method-combination` (R5.79)

Stores method-group-specifiers and a body form.  At effective-method time:
(1) partition applicable methods into groups, (2) evaluate body → `call-method`
form, (3) compile to effective method closure.

## 5.3.10  `make-instance` Protocol (R5.80, R5.81)

```text
(make-instance class &rest initargs)
  ├─ 1. Validate initargs (slot initargs ∪ initialize-instance/shared-initialize kwargs)
  ├─ 2. (allocate-instance class) → header + N slots filled with +slot-unbound+
  ├─ 3. (initialize-instance instance initargs)
  │     └─ (shared-initialize instance T initargs)
  │         for each slot: initarg supplied → set; else initform → eval+set; else unbound
  └─ 4. Return instance
```

`reinitialize-instance` calls `(shared-initialize instance NIL initargs)` — no
initforms evaluated, only explicit initargs applied (R5.81).

`allocate-instance` (Rust): `heap::alloc(16 + 8*slot_count)`, set header/wrapper,
fill slots with `SLOT_UNBOUND`.

---

## 5.3.11  `change-class` Protocol (R5.82)

1. Snapshot old instance state.
2. Copy shared slot values (slots in both old and new class).
3. Atomically swap wrapper → new-class wrapper; resize slot vector if needed.
4. Call `(update-instance-for-different-class old-snapshot instance initargs)`.
   Default method calls `shared-initialize` on added slots.

**Thread safety:** instance-level lock (via object header metadata) ensures
concurrent slot access sees either old or new state, never torn.

---

## 5.3.12  Class Redefinition & Obsolete Instances (R5.83, R5.84)

### Redefinition trigger (on re-evaluation of `defclass`)

1. Compute new slots/CPL.  Allocate new ClassWrapper with fresh stamp.
2. Atomically set old wrapper state → `:obsolete`.
3. Update class metaobject (effective-slots, CPL, wrapper, stamp).
4. Invalidate dispatch caches for GFs specializing on this class (R5.85).
5. Do **not** eagerly update existing instances — lazy update follows.

### Lazy obsolete-instance update (A5.04)

Every slot access checks `instance.wrapper.state`:
- `:current` → proceed.
- `:obsolete` → call `UPDATE-OBSOLETE-INSTANCE`.

The exactly-once guarantee (R5.84) is enforced by a CAS on the
**instance's own wrapper pointer field** (per-instance), NOT on
the shared `ClassWrapper.state` (which is per-class and merely
marks all instances of that class as needing update).

```text
UPDATE-OBSOLETE-INSTANCE(instance):
    old-wrapper ← instance.wrapper               ;; snapshot
    if old-wrapper.state ≠ :obsolete: return      ;; already current
    new-wrapper ← old-wrapper.class-ref.wrapper   ;; class's current wrapper
    ;; Per-instance CAS: only one thread wins for THIS instance
    if ¬ CAS(instance.wrapper, old-wrapper → UPDATING_SENTINEL): return  ;; another thread is handling it
    Compute slot diffs (added/removed/shared) between old-wrapper and new-wrapper
    Build removed-plist of (name value ...) for bound removed slots
    Resize slot vector; copy shared slots to new indices; mark added as unbound
    Set instance.wrapper ← new-wrapper            ;; publish (store-release)
    Call (update-instance-for-redefined-class instance added removed removed-plist)
```

The CAS on the instance's wrapper pointer allows concurrent updates of
**different** instances of the same class to proceed in parallel, while
guaranteeing exactly-once semantics per instance.  `UPDATING_SENTINEL` is
a distinguished pointer value (aligned, non-null) that causes any concurrent
accessor to spin-wait until the update completes (wrapper becomes `:current`).

## 5.3.13  `class-of` and Built-in Classes (R5.87, R5.89)

`class-of` resolves via tag bits (§1): immediate types (fixnum, cons, character,
single-float, symbol) → static built-in-class objects; heap objects / functions →
`instance.wrapper.class-ref`.  O(1): one mask + branch + at most one load (R5.89).

Built-in classes participate in the hierarchy but `allocate-instance` signals
an error (R5.87).

### Metaclasses (R5.88)

| Metaclass | Purpose | Instance layout |
|-----------|---------|-----------------|
| `standard-class` | User-defined classes | Header + wrapper + slot vector |
| `funcallable-standard-class` | GF classes | Header + wrapper + entry-point + slots |
| `built-in-class` | Fixnum, cons, etc. | N/A (error on allocate) |
| `structure-class` | `defstruct` classes | Fixed typed struct layout (§5.4) |

`funcallable-standard-class` adds an entry-point word at offset 16; slots
shift to offset 24.

## 5.3.14  Error Handling

| Condition | When | Type |
|-----------|------|------|
| Slot unbound | `slot-value` on unbound slot | `unbound-slot` (cell-error) |
| Slot missing | `slot-value` on nonexistent slot | `simple-error` via `slot-missing` |
| C3 inconsistency | `compute-class-precedence-list` | `error` |
| Invalid initarg | `make-instance`/`reinitialize-instance` | `error` |
| No applicable method | GF call with no match | `error` via `no-applicable-method` |
| No next method | `call-next-method` at chain end | `error` via `no-next-method` |
| Built-in alloc | `allocate-instance` on built-in-class | `error` |

## 5.3.15  Concurrency

| Resource | Mechanism | Notes |
|----------|-----------|-------|
| Class metaobject slots | RW-lock per class | Reads: shared; redefinition: exclusive |
| ClassWrapper state | Atomic u8 | Lock-free stamp check on every slot access |
| Dispatch cache | Per-GF spinlock (write), lock-free read | Generation-based invalidation |
| Obsolete instance update | CAS on instance's wrapper pointer | Per-instance exactly-once guarantee |
| GF method table | Per-GF RW-lock | Add/remove: exclusive; dispatch: shared |
| Global stamp counter | Atomic u64 fetch-add | Contention-free; never recycled |
