# x86-64 Native Lisp ABI — Proposed Contract

Companion to [§4.7 Code Generation](04-07-codegen.md). Status: **target design,
not implemented by v0.0.6**. Implementation milestone: `bliss-t8a48`.
This document fixes the proposed baseline convention for ordinary compiled Lisp
calls. It does not claim implementation coverage, advance a build stage, or
replace the current transfer ABI version 3. Adoption needs a distinct published
entry-kind/version so an old frame-slot entry is never called with this layout.

## Scope and design choices

Register passing is the normal compiled-to-compiled convention, including
self-recursion. Managed activation construction belongs at interpreter and
other runtime transitions, rather than on every native call. Initial rollout
can restrict eligible callees; those restrictions are not the final ABI.

The baseline uses tagged 64-bit `EgclVal` arguments. It follows SBCL's ordinary
x86-64 argument register assignment (`RDI`, `RSI`, `RDX`) and separates count,
closure and execution context. It retains EGCL's existing primary/MV return
protocol to avoid coupling call improvements to a return-storage redesign.
It is **not binary compatible with SBCL**: count encoding, returns, object
representation and runtime metadata differ. The pinned SBCL sources are in
[§4.7.4.4](04-07-codegen.md#4744-comparison-with-sbcl-and-remaining-work).

This contract covers x86-64 Linux native Lisp entries. C/Rust helpers continue
to use System V; Windows and other host adapters need separate specifications.
Specialized unboxed local conventions are outside this baseline and require
explicitly compatible entry descriptors on both sides.

## Register contract

| Register | At Lisp entry | At normal return / preservation |
|----------|---------------|---------------------------------|
| `RDI` | Argument 1, when present | Caller-clobbered |
| `RSI` | Argument 2, when present | Caller-clobbered |
| `RDX` | Argument 3, when present | MV count when `CF=1`; otherwise unspecified |
| `RCX` | Number of supplied arguments, unsigned untagged 64-bit integer | Borrowed MV tuple pointer when `CF=1`; otherwise unspecified |
| `RAX` | Tagged callee closure/function object, or `NIL` for an entry with no environment | Primary result; `NIL` for zero values |
| `R13` | Raw current Lisp execution-context pointer | Preserved across ordinary calls |
| `R10`, `R11` | Scratch, no incoming value contract | Caller-clobbered |
| `R8`, `R9` | Scratch, no incoming value contract | Caller-clobbered |
| `RBX`, `R12`, `R14`, `R15` | Available to allocation | Callee-preserved |
| `RBP` | Caller frame pointer | Callee-preserved; standard frame chain below |
| `RSP` | Points to return address | Restored by callee and `RET`; caller releases argument area |
| `XMM0`–`XMM15` | No baseline Lisp arguments | Caller-clobbered |
| Flags | Direction flag clear; other flags unspecified | Direction flag clear; carry encodes result multiplicity |

Unused argument registers are unspecified and are not roots merely because
of their register names. A general entry validates `RCX` against its lambda
list before consuming arguments. Counts include only explicit supplied Lisp
arguments, not the closure or execution context; omitted optional arguments
remain omitted. Complex lambda-list binding may use an adapter initially.

The entry descriptor determines whether `RAX` contains a closure or `NIL`.
A closure is a tagged rooted value, not a raw pointer into its movable payload.
The execution context is execution/fiber-owned, not a carrier-thread identity;
its address is stable while native frames reference it. This implements the
existing planned `R13` contract, R4.72/R4.73 [S6]. Rust helpers receive it as an
explicit C argument, never by reading an assumed live `R13` with inline asm.

## Stack arguments and frames

The caller owns an outgoing argument area. Arguments four onward occupy
contiguous eight-byte slots in source order. At callee entry:

```text
[RSP + 0]   return address
[RSP + 8]   argument 4, if present
[RSP + 16]  argument 5, if present
...         remaining arguments
...         optional alignment padding (not an argument or root)
```

Immediately before `CALL`, `RSP` is 16-byte aligned; on entry it is 8 modulo
16. The caller allocates an area whose size rounds the overflow argument bytes
up to a multiple of 16, assuming its normal call boundary is aligned. Padding
follows the final argument. There is no red-zone use and no C-style shadow
space. Every additional helper call independently satisfies host alignment.

The baseline prologue saves `RBP` and establishes `RBP = RSP`; consequently
`[RBP]` is the saved frame pointer, `[RBP+8]` the return address, and `[RBP+16]`
argument four. Locals, spills and saved registers are below `RBP`. Their exact
layout is code-specific and described by unwind and value-location metadata.
The callee restores its saves and returns with plain `RET`, not `RET imm`.

After return the caller releases its outgoing area with flag-preserving
instructions, such as `LEA`, until it has consumed or saved the carry result.
It also preserves `RAX`, and `RDX`/`RCX` for a zero/many result, until consumed.
Callee-preserved Lisp values preserve their identity, not stale pointer bits:
moving GC may update both saved homes and the registers restored from them.

## Returns and multiple values

| Result | `RAX` | Carry | `RDX` | `RCX` |
|--------|-------|-------|-------|-------|
| Exactly one value | That value | Clear | Unspecified | Unspecified |
| Zero values | `NIL` | Set | 0 | Null |
| Two or more values | First value | Set | Full unsigned count | Pointer to all values, including the first |

The execution's `Env` owns and traces the materialized MV tuple. Its borrowed
pointer is valid only until tuple mutation, GC, or suspension. A caller that
needs values across another call copies them into traced homes first; the raw
tuple pointer itself is not a root. The `RAX` copy of a heap primary also needs
a mapped home if it survives a collecting boundary.

Mapped entry begins with the MV buffer empty and inactive. The caller clears
prior MV state when necessary, after saving any needed values; proof that it is
already empty permits omission. A single return leaves it empty and inactive.
An arbitrary single-result path clears outstanding tuple state before returning;
a path proven to return one value with the buffer already empty and inactive
needs only its result and `CLC`. Zero/many returns establish
the materialized tuple and descriptor. Final carry is set after any epilogue
instruction that changes flags. Adapters reconstruct this descriptor after
interpreter execution or runtime retirement, as in the current mapped protocol.

Carry is not an error indicator. Conditions, nonlocal exits and deoptimization
use runtime control-transfer machinery, with the root/unwind obligations below.
Small multiple-value tuples in separate value registers are a later extension.

## Calls, linkage and redefinition

A published entry descriptor identifies ABI kind/version, code owner, supported
signature, environment convention and invalidation/generation information.
Callers select a compatible entry before committing to its register layout.
A linkage stub can resolve a target, but preserves or explicitly marshals all
incoming arguments, count, closure and context before any collecting helper.

Named calls respect current function bindings. A direct target is legal only
under the runtime's generation/invalidation protocol; an unchecked cached code
address is insufficient. Active frames retain their code and metadata owners
through return, unwind or deoptimization. Replacement prevents new invalid
entries without freeing code still referenced by suspended frames. Calling a
previously captured function object retains that object's semantics, rather
than silently resolving its original name to a replacement definition.

The initial implementation can support fixed arity zero through four: the
fourth argument already exercises the overflow-stack rule. It uses this same
ABI for self-calls and different-function calls; the current four-register
self-recursive convention is a legacy entry needing migration or an adapter.

## GC, safepoints and interpreter transitions

Every collecting or deoptimizing boundary has exact-PC metadata identifying
live tagged values, writable stack/saved-register homes, unwind information,
and the owning compiled code. Caller values live across calls, incoming
arguments, closures and overflow arguments are included when live. Padding,
raw control pointers and dead argument slots are excluded.

Argument handoff has no untracked collecting window: before its first safepoint
a callee publishes incoming live values to mapped homes, or uses an entry map
and trampoline capable of exposing and updating those registers. The caller's
return-PC map describes its suspended state. A collecting adapter first roots
its complete incoming argument set. Generated code reloads relocated values
from their updated homes before reuse.

Native frame chains may contain different code owners. GC and deoptimization
walk each frame using its own metadata. Interpreter-compatible frames are
materialized at cold boundaries when required; a managed anchor at a native
segment boundary does not imply a managed activation for each native child.
Guard failure reconstructs the correct continuation without replaying completed
side effects. Unwind handles cleanup and dynamic bindings through registered
runtime control state; no host exception unwinds through an undescribed frame.

Interpreter-to-native adapters marshal slots to registers/stack. Native-to-
interpreter adapters root arguments, construct managed state, and translate
returns. C helpers use System V register marshaling and explicit context
arguments; their carry flag has no Lisp meaning. Fiber switching preserves
`R13` and the native stack; safepoints and stack checks preserve existing GC,
signal, cancellation, depth and overflow semantics. This ABI does not grant
arbitrary asynchronous collection of unrecorded register state.

## Tail calls

A tail transfer uses the same argument, count, closure and context contract.
It restores the caller's callee-saved state and reuses its incoming return
address. The target returns directly to the original caller, which still owns
and releases the original overflow area.

The baseline permits a tail jump only when target overflow arguments fit within
the current function's incoming overflow capacity (rounded as above), and no
pending cleanup, dynamic-binding or other control obligation requires retaining
the frame. Overlapping argument moves preserve all source values. Metadata and
code-owner retirement remain valid through the handoff. Otherwise emit an
ordinary call and return; growing a tail argument area requires a separately
specified protocol. Tail transfer also establishes the normal empty MV entry
state and forwards the callee's result without changing its carry descriptor.

## Worked call

For a known environment-free `(callee a b c d)`, after saving caller-live values
and preparing any required MV clear:

```asm
; Schematic: caller frame already has RSP aligned to 16 bytes.
; a/b/c/d denote values in safe homes, not assembler operands.
sub rsp, 16           ; argument 4 plus 8 bytes padding
mov [rsp], d
mov rdi, a
mov rsi, b
mov rdx, c
mov rcx, 4            ; untagged supplied count
mov rax, NIL          ; target needs no closure
; R13 already identifies this Lisp execution.
call compatible_entry ; linkage/generation checks are assumed here
lea rsp, [rsp+16]     ; preserve CF and return descriptor
jc zero_or_many
; RAX is the sole result.
```

This is an ABI illustration, not a complete safe code-emission template:
parallel argument moves, entry validation, code lifetime and exact-PC root
publication still follow the contracts above. Acceptance and rollout are in
[§11.4.3](11-phasing-roadmap.md#1143-x86-64-native-cross-function-calls).
