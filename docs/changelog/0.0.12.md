## 0.0.12 - 2026-11-03

### Added

- `WITH-POINTER-TO-VECTOR-DATA` accepts packed octet and double-float vectors
  through the existing foreign-memory copy-in/copy-out interface
  ([#722](https://github.com/atgreen/evergreen/pull/722)).

- Add opt-in execution-owned T1 sampling countdowns on x86-64 Linux with
  `EGCL_EXECUTION_T1_HEAT=1`
  ([#983](https://github.com/atgreen/evergreen/pull/983)).

- Add opt-in execution-context linkage for ordinary x86-64 Linux calls with
  `EGCL_R13_CALL_LINKAGE=1`
  ([#982](https://github.com/atgreen/evergreen/pull/982)).

- Add opt-in eager T1 compilation for named FASL-loaded functions and their
  nested closure templates with `EGCL_FASL_EAGER_T1=1`
  ([#981](https://github.com/atgreen/evergreen/pull/981)).

- Extend character and string storage to preserve surrogate character codes,
  with remaining stream, reader and formatting limitations
  ([#980](https://github.com/atgreen/evergreen/pull/980)).

- Add an experimental iOS Xcode project generator with bundled Lisp source,
  host-worker UI integration and SDK-selected static-runtime linking. Generated
  projects and Apple execution remain unvalidated
  ([#910](https://github.com/atgreen/evergreen/pull/910)).

- Add an initial iOS C worker-host API and SwiftUI source scaffold with
  cooperative Lisp shutdown, preserved host control signals, scoped application
  paths and explicit subprocess rejection. Full app/device validation remains
  pending ([#909](https://github.com/atgreen/evergreen/pull/909)).

- Add an ARM64 iOS device/simulator foundation with Darwin OS routing and an
  enforced T0/no-executable-memory profile. Full application support and
  SDK/device validation remain unfinished
  ([#899](https://github.com/atgreen/evergreen/pull/899)).

- Static applications can link foreign native archives declared with
  `EGCL_STATIC_FOREIGN_MANIFEST`, exposing listed C functions and data through
  the existing FFI APIs without shipping shared libraries
  ([#887](https://github.com/atgreen/evergreen/pull/887)).

### Changed

- FILL on bit-vectors, `(unsigned-byte 8)` and double-float vectors and
  fill-pointer vectors runs natively a byte or word at a time instead of
  element by element, and REPLACE copies bit-vectors 64 bits at a time and
  packed vectors with one memmove: filling a 10,000-bit vector went from
  30 ms to 12 us. SYMBOL-PACKAGE, STRING and SYMBOL-NAME of a symbol,
  FIND-SYMBOL and GET do less work per call; SYMBOL-PACKAGE's own work fell
  about ninefold ([#976](https://github.com/atgreen/evergreen/pull/976)).

- EQUAL and EQUALP hash tables and SXHASH hash every element of a list, to a
  bounded nesting depth and total length, instead of only its first few, so
  keys such as `(AND (INTEGER 0 1))` and `(AND (INTEGER 0 2))` no longer
  collide. A 10,000-key table of type-specifier lists went from 2,503 distinct
  hashes to 10,000 and from 73 us to 4.4 us per lookup. SXHASH called from
  compiled code no longer goes through the evaluator
  ([#974](https://github.com/atgreen/evergreen/pull/974)).

- DEFSTRUCT accessors are ordinary functions, as in SBCL: calling one on an
  object of the wrong type signals TYPE-ERROR, DEFMETHOD no longer extends it,
  and an included structure's writer checks the slot type the included
  structure declared ([#948](https://github.com/atgreen/evergreen/pull/948)).

- Avoid redundant rational normalization and unit-denominator arithmetic for
  exact integer addition, subtraction, multiplication and comparison
  ([#930](https://github.com/atgreen/evergreen/pull/930)).

- Read each function's call-site counters directly when preparing T2 compilation,
  avoiding scans of unrelated profiles
  ([#925](https://github.com/atgreen/evergreen/pull/925)).

- Reduce ordinary native-call overhead by indexing retained callable checks by
  code owner instead of scanning every retained descriptor
  ([#922](https://github.com/atgreen/evergreen/pull/922)).

- Construct filled simple bit vectors through the MAKE-ARRAY fast path, avoiding
  repeated keyword scans and temporary lists of bits
  ([#919](https://github.com/atgreen/evergreen/pull/919)).

- AArch64 T2 right-shifts a one-limb bignum natively instead of calling the
  runtime, so `(ASH x -n)` over bignums costs 15x less — down from 48x the
  price of a fixnum shift to 3x
  ([#840](https://github.com/atgreen/evergreen/pull/840)).

- AArch64 T2 writes a fused integer-to-octet loop as one wide store instead of
  calling the runtime per byte, measuring 1.09x on the loop it replaces
  ([#854](https://github.com/atgreen/evergreen/pull/854)).

- AArch64 T2 reads and writes vector elements inline instead of calling the
  runtime, so `AREF`, `SVREF`, `ELT` and `(SETF AREF)` on simple vectors and
  packed `(unsigned-byte 8)` arrays cost 30x to 43x less per access
  ([#760](https://github.com/atgreen/evergreen/pull/760)).

- Source closures inside unused lexical function bindings can enter tiered
  compilation, including generated string encoders and counters; closures that

### Performance

- Native RPM runtimes use profile-guided builds trained separately for their

- AArch64 T2 reaches portable-call adapters for closure creation and avoids

  [#750](https://github.com/atgreen/evergreen/pull/750)).

- System Z compiles more fixnum division and single-float comparisons natively,

  [#758](https://github.com/atgreen/evergreen/pull/758),
  [#852](https://github.com/atgreen/evergreen/pull/852),
  [#757](https://github.com/atgreen/evergreen/pull/757)).

- Reuse initialized native bridge contexts across parent calls on x86-64 Linux,
  avoiding repeated context construction while refreshing execution controls
  and preserving immediate code retirement
  ([#992](https://github.com/atgreen/evergreen/pull/992)).

- Reuse ordinary native bridges for eligible T1 function-object calls from
  mapped code. Retain eligible bridge contexts within each caller beyond
  its four generated bindings, avoiding repeated activation and context setup
  while preserving invocation counts and tier promotion boundaries
  ([#990](https://github.com/atgreen/evergreen/pull/990)).

- Route eligible mapped T1/T2 calls and T2 `FUNCALL` targets through existing
  ordinary native entries, avoiding repeated managed child activation setup.
  Reuse clean native bridge storage across parent calls while refreshing each
  call's execution context. In the measured x86-64 Linux `sset`
  cross-compilation phase, median elapsed time falls by 4.2%
  ([#989](https://github.com/atgreen/evergreen/pull/989)).

- Add experimental lazy native-frame publication, broader T1 loop entries
  and batched polling, native closure string access, and wider generic-call
  caches ([#980](https://github.com/atgreen/evergreen/pull/980)).

- More functions compile instead of running in the interpreter on every
  call: functions with a parameter named by a special variable (such as
  `(&key ((:lossage-fun *lossage-fun*)))`), inline `((lambda (x &aux ...))
  ...)` applications, and DESTRUCTURING-BIND inside a lambda in compiled
  top-level code. A special parameter is still bound dynamically and
  restored on exit. Keyword-default visibility remains experimental.
  ([#980](https://github.com/atgreen/evergreen/pull/980))
- On x86-64 Linux, optimized code answers ATOM, LISTP, SYMBOLP, PLUSP,
  MINUSP, BIT, SBIT, GET, three-argument LOGAND/LOGIOR/LOGXOR, and TYPEP of a
  structure type name without the general runtime call: about 11 ns a call
  instead of 280-300 ns, GET 50 ns instead of 3 us, and a structure TYPEP 130
  ns instead of 500 ns. Compiling SBCL's `src/compiler/sset` while hosting its
  cross-compiler takes 7% less time. `EGCL_BUILTIN_CENSUS=<path>` writes a
  count of the calls that still take the general route, by callee and route
  ([#975](https://github.com/atgreen/evergreen/pull/975)).

- On x86-64 Linux, eligible optimized FUNCALL sites enter function objects
  and closures through their native entry words. Closure instances share a
  template dispatch stub that follows code replacement and preserves the
  runtime fallback for other executions and unsupported callees.
  `EGCL_LEAN_FUNCALL=0` selects the previous route
  ([#977](https://github.com/atgreen/evergreen/pull/977)).

- More functions that create closures now compile instead of running in the
  interpreter: a closure over a MULTIPLE-VALUE-BIND variable, a HANDLER-CASE
  clause variable, or a local function's parameter no longer forces its whole
  function onto the tree-walker. Compiling SBCL's `sset.lisp` under EGCL makes
  a quarter as many interpreted calls (81,239 → 20,209) and takes about 25%
  less time. On x86-64 Linux, optimized code now reads a closure's captured
  variables directly from the closure, so recursive LABELS functions over
  captured variables run about 28x faster at T2 and a deep captured read takes
  4.5 ns instead of 18. `EGCL_HEAP_ENV_LABELS=0` keeps recursive LABELS
  functions on the previous representation. The image format is now version
  20; images saved by earlier versions must be saved again.
  ([#973](https://github.com/atgreen/evergreen/pull/973))
- On x86-64 Linux, more optimized functions use the fast native calling
  convention instead of a slower entry that goes through the runtime:
  functions with `&rest` lists, with `&optional` parameters beyond the
  third, or with `&key` lists of any size (including `&allow-other-keys`);
  calls passing eight or more arguments; functions that return multiple
  values with `VALUES`; and callers that bind multiple values with
  `MULTIPLE-VALUE-BIND`. `FUNCALL` of a compiled function with up to 15
  arguments also stays native.
  `EGCL_DISABLE_ORDINARY_VALUES=1` keeps multiple-value functions on the old
  path for comparison.
  ([#980](https://github.com/atgreen/evergreen/pull/980))
- On x86-64 Linux, a compiled call from one optimized function to another
  named, fixed-arity, optimized function is cheaper. The function object now
  carries its own native entry, so the caller loads the name's current
  definition and calls that entry directly; the callee checks its own stack.
  The `native-call4` benchmark drops from 13 to 10 ms, and a chain of three
  such calls runs about 15% faster per iteration. Redefining a function
  still takes effect at the next call. Saved images
  from earlier versions must be rebuilt (image format 19).
  ([#972](https://github.com/atgreen/evergreen/pull/972))
- A `(lambda ...)` inside code compiled for speed (for example a
  `compile-file`d top-level form) is now compiled as a closure instead of
  being handed to the interpreter each time it is created, so the enclosing
  function stays compiled. `EGCL_LAMBDA_HOST_HANDOFF=1` restores the old
  behaviour for comparison.
  ([#969](https://github.com/atgreen/evergreen/pull/969))
- On x86-64 Linux, closures that read or assign captured variables run
  faster in native code. A variable a closure captures but never assigns is
  copied into the closure, and one it assigns lives in a heap environment
  that compiled code reads and writes directly, with no lookup by name: a
  captured read three LETs deep falls from 230 to 18 ns at T2, and nested
  LETs whose variables a closure captures run about 1.75x faster at every
  tier. `EGCL_HEAP_ENV=0` restores the previous representation.
  ([#971](https://github.com/atgreen/evergreen/pull/971))
- Functions using DESTRUCTURING-BIND with `&whole`, `&key` or `&aux`,
  `(setf (getf place key) ...)`, HANDLER-CASE with a `:no-error` clause, or
  HANDLER-BIND on an `(or ...)` or `(satisfies ...)` type now compile instead
  of running in the interpreter on every call. A compiled DESTRUCTURING-BIND
  now signals PROGRAM-ERROR for an unknown or malformed keyword list.
  ([#970](https://github.com/atgreen/evergreen/pull/970))
- Closures are cheaper to create, call and collect. Every closure made from
  one LAMBDA shares a single compiled body and tiering record, and carries
  its captured variables on the function object itself, so creating one is a
  single allocation: creating a capturing closure is 2.5–3x faster, and
  garbage-collection time in loops that create closures drops by about 80%.
  A LAMBDA that captures nothing now returns the same function object every
  time it is evaluated, so such closures are `eq`. The image format is now
  version 18; images saved by earlier versions must be saved again.
  ([#968](https://github.com/atgreen/evergreen/pull/968))
- Functions containing MULTIPLE-VALUE-SETQ, an inline `((lambda (x) ...) arg)`
  application, `(setf (get ...))`, or a HANDLER-CASE clause typed

  call. SBCL's cross-compiler kept its globaldb lookups interpreted this way;

  ([#967](https://github.com/atgreen/evergreen/pull/967))
- MAPC, MAPCAR, MAPCAN, MAPL, MAPLIST, MAPCON, SOME, EVERY, NOTANY and
  NOTEVERY over up to four lists are compiled into inline loops: a literal
  LAMBDA argument runs without creating a closure, and a call over a short
  list is up to several hundred times cheaper (about 37 us down to under 1 us
  for three elements). Compiled `(setf (car x) ...)` and `(setf (cdr x) ...)`

  ([#965](https://github.com/atgreen/evergreen/pull/965))
- Creating a closure is about 30% cheaper. Minor garbage collections no
  longer re-trace the captured variables of every live closure (pauses with
  ~50k closures alive fell from 150-170 ms to 27-45 ms), and each new closure

  about 3% faster.
  ([#964](https://github.com/atgreen/evergreen/pull/964))
- Functions whose closures RETURN-FROM an enclosing BLOCK, and the closures
  themselves, now compile to native code instead of staying in the bytecode
  interpreter, as do functions whose local RETURN or GO leaves a LET binding
  that a closure captures. A closure that GOes to an enclosing TAGBODY also
  compiles natively; the function it jumps back into still runs interpreted.
  ([#963](https://github.com/atgreen/evergreen/pull/963))
- Minor garbage collections no longer rescan the captured variables of every
  live interpreted closure. Each collection visits only the lexical frames and
  function bodies written since the last one, which cuts minor-collection
  pause time about fourfold in closure-heavy programs and makes the first
  compilation of SBCL's own sources about 2 seconds faster.
  `EGCL_GC_REMEMBERED_CAPTURES=0` restores the old full rescan.
  ([#962](https://github.com/atgreen/evergreen/pull/962))
- Compiled functions that bind special variables with LET or LAMBDA, and use
  no other dynamic scope, stay in the fastest native tier instead of the
  slower mapped one. Binding a special variable and reading it in a callee
  takes about 150 ns per call instead of about 7.8 us.
  ([#961](https://github.com/atgreen/evergreen/pull/961))
- Compiled AREF and SVREF reads and stores on adjustable, fill-pointer and bit
  vectors call the general accessor instead of falling back to the
  interpreter, and functions whose BLOCK or TAGBODY sits in an argument
  position, or that access structures inside an UNWIND-PROTECT or handler,
  now compile natively. A loop over adjustable and bit vectors runs about 45
  times faster ([#955](https://github.com/atgreen/evergreen/pull/955)).
- On x86-64 Linux, small pieces of compiled native code now share executable
  pages instead of each taking its own memory mapping. A long-running build of
  SBCL hosted on EGCL uses about half the memory (2.66 GB → 1.29 GB peak by
  its 24th file) and roughly 1/16th the executable memory, and no longer
  approaches the kernel's mapping limit
  ([#956](https://github.com/atgreen/evergreen/pull/956)).
- `--heap-size` is honored again, typed DEFSTRUCT constructors and writers
  compile natively instead of staying interpreted, and a function whose native
  code keeps failing the same guard stays at T1 instead of being recompiled

  28% ([#953](https://github.com/atgreen/evergreen/pull/953)).

  never call CALL-NEXT-METHOD no longer build a method continuation, and
  SLOT-VALUE in methods no longer takes the full MOP path. A warm monomorphic
  generic call takes about 4.8 us instead of 34 us, and an `:accessor` reader

  dispatch, and BIT-AND and the other bit-array functions work bytewise. A

  ([#688](https://github.com/atgreen/evergreen/pull/688)).

  takes 0.019 s instead of 6.3 s. A double loop that calls a function goes
  native too, but its calls are still slow in that first call: 4,000,000
  iterations take 2.9 s instead of 9.6 s, and 0.11 s from the next call on
  ([#649](https://github.com/atgreen/evergreen/pull/649), reported in
  [#642](https://github.com/atgreen/evergreen/issues/642)).
- On x86-64 Linux, a loop typed at the REPL, given to `--eval` or written at
  the top level of a loaded file now leaves the interpreter part-way through,
  as a loop in a once-called function already did: after 100,000 iterations
  the running loop continues in native code. So does a loop in a closure,
  such as `(funcall (make-adder) n)` on a `(lambda ...)` that loops. `time`
  is now compiled instead of interpreted, so `(time (dotimes ...))` and
  `(print (time ...))` measure compiled code; before, everything inside `time`
  was evaluated by the slow tree-walker. `loop for i below n` inside a `let`
  is compiled too. Without any warm-up, 10,000,000 iterations of a top-level
  fixnum sum loop take 0.24 s instead of 14.4 s; inside `time` they take the
  same 0.24 s, where they used to take about 22 minutes. A top-level loop
  that calls a function takes 5.5 s instead of 17.5 s, a consing loop 3.1 s
  instead of 18.9 s, and `(loop for i below n sum i)` 0.23 s instead of more
  than 5 minutes. A loop that increments a special variable still runs at
  about 1 us per iteration
  ([#637](https://github.com/atgreen/evergreen/pull/637)).
- On x86-64 Linux, compiled code reads and assigns a special variable
  directly in its value cell when no thread or fiber has it dynamically
  bound, instead of calling into the runtime for every access. Bound,
  unbound and constant variables still take the runtime path, so `let`,
  `progv`, per-thread bindings, unbound-variable errors and assignments to
  constants behave as before. 10,000,000 iterations of
  `(dotimes (i n) (incf *x* i))` take 0.6 s instead of 9.3 s, in a function
  or at top level, and a loop that only reads a special takes 0.36 s instead
  of 3.3 s. A loop that runs inside a `let` binding of a special variable
  now leaves the interpreter like any other hot loop: 10,000,000 iterations
  of `(let ((*x* 0)) (dotimes (i n) (incf *x* i)))` take 8.4 s instead of 22 s
  ([#639](https://github.com/atgreen/evergreen/pull/639)).
- On x86-64 Linux, a long-running loop whose arithmetic changes type part-way
  through, for example a fixnum sum that becomes a single-float or overflows
  into a bignum, returns to native code after the change instead of
  finishing that call in the interpreter. Once the loop has run another
  100,000 iterations, the code that made the wrong assumption is replaced
  with code compiled for the new types. One call of
  `(dotimes (i 8000000) (setq acc (+ acc (if (< i 4000000) 1 1.0f0))))` takes
  0.6 s instead of 7.4 s. A loop can switch code a limited number of times,
  so a value that keeps changing type ends up in generic native code
  rather than recompiling for every change. Loops that move to double-floats
  still finish in the interpreter
  ([#646](https://github.com/atgreen/evergreen/pull/646)).

### Fixed

- Two places that packed `(unsigned-byte 8)` arrays missed, each of which
  broke every `ocicl install`
  ([#755](https://github.com/atgreen/evergreen/pull/755)):
  - Ironclad's SHA3 and other Keccak digests work again. The native Keccak
    absorb rejected Ironclad's packed buffer as "not of type "an octet
    vector"". It now reads packed and general octet vectors alike, as the
    other crypto kernels already did.
  - `egcl-ext:string-to-octets` returns an `(unsigned-byte 8)` vector, and
    `egcl-ext:octets-to-string` accepts any vector of octets again. The
    encoder still made a general vector, which the decoder's
    `(vector (unsigned-byte 8))` check now rejected, so pure-tls could not
    parse a single PEM certificate and trusted no CA.

- `ADJUST-ARRAY` preserves adjustable array identity, multidimensional shape,
  element storage, displacement aliases, and fill-pointer options. Bounded
  bit-equivalent element types consistently use bit storage, and `SVREF`
  validates arity before array type. BFASL and saved images retain mutable
  array storage graphs and shared references
  ([#742](https://github.com/atgreen/evergreen/pull/742)).

- Nonlocal `RETURN-FROM` from bytecode closures preserves zero and multiple
  values through named block exits and cleanup
  ([#747](https://github.com/atgreen/evergreen/pull/747)).

- Qualified SETF function names retain their identity through compiled files
  and saved images without creating bogus packages
  ([#739](https://github.com/atgreen/evergreen/pull/739)).

- The `#nA` reader accepts packed `(unsigned-byte 8)` vectors as contents,
  including empty vectors and multidimensional rows
  ([#721](https://github.com/atgreen/evergreen/pull/721)).

- `COMPILE-FILE` keeps ordinary function definitions out of the compiling image
  and honors output pathnames, printing options, and style versus ordinary
  warning flags. `LOAD` honors output options
  and copied reader-macro operations, and `REQUIRE` accepts explicit pathnames
  ([#738](https://github.com/atgreen/evergreen/pull/738)).

- Interpreted `MULTIPLE-VALUE-BIND` preserves uninterned variable identity,
  preventing fresh SETF-expander store variables from permanently retaining
  their generated names during workloads such as TLS I/O
  ([#729](https://github.com/atgreen/evergreen/pull/729)).

- `FORMAT` treats `~:T` and `~:@T` outside a logical block as no-ops, including
  when pretty printing is enabled, while preserving tabulation within blocks
  ([#726](https://github.com/atgreen/evergreen/pull/726)).

- Pretty-printer `:FILL` conditional newlines behave like `:LINEAR` while
  miser mode is active, preserving ordinary section filling otherwise
  ([#727](https://github.com/atgreen/evergreen/pull/727)).

- `FORMAT` preserves conditional layout emitted by pprint dispatch methods,
  `FORMATTER` iteration bodies, and `~/.../` callbacks, including destination
  columns and the `~W` colon/at-sign printer bindings
  ([#723](https://github.com/atgreen/evergreen/pull/723)).

- `FORMAT` logical blocks and public pretty printing share one semantic layout
  engine, preserving conditional breaks, indentation, tabs, case conversion,
  printer limits, circular output, and Gray-stream behavior
  ([#718](https://github.com/atgreen/evergreen/pull/718)).

- `import` now signals a correctable package conflict when a distinct
  same-named symbol is inherited by the target package; continuing preserves
  the inherited binding
  ([#714](https://github.com/atgreen/evergreen/pull/714)).

- Strings opened by a character given double-quote syntax now end at that
  character, and characters given single-escape syntax quote the next character
  while reading a string
  ([#695](https://github.com/atgreen/evergreen/pull/695)).

- Class precedence lists follow Common Lisp's specified topological ordering
  where it differs from C3, preserving the standard method and slot precedence
  for nonmonotonic multiple-inheritance graphs
  ([#696](https://github.com/atgreen/evergreen/pull/696)).

- Effective class `:default-initargs` follow the class precedence list, so the
  most specific inherited default wins in multiple-inheritance hierarchies
  ([#697](https://github.com/atgreen/evergreen/pull/697)).

- `symbol-package` continues to report `COMMON-LISP` for its symbols after
  another package re-exports them, independent of package registry order
  ([#698](https://github.com/atgreen/evergreen/pull/698)).

- `#S` structure literals accept character and string designators for slot
  names, including names that contain package-marker characters
  ([#694](https://github.com/atgreen/evergreen/pull/694)).

- `type-of` reports character, array, function, method, random-state, and
  built-in object types that `subtypep` places under the object's classes;
  adjustable, fill-pointered, and displaced vectors no longer satisfy
  `simple-array`
  ([#702](https://github.com/atgreen/evergreen/pull/702)).

- `NOTINLINE` declarations remain effective through native specialization,
  while preserving argument evaluation and lookup of redefined functions
  ([#703](https://github.com/atgreen/evergreen/pull/703)).

- `WRITE-TO-STRING` honors printer controls under every forced tier during
  bootstrap, avoiding an undefined-function error from a later macro definition
  ([#700](https://github.com/atgreen/evergreen/pull/700)).

- `defstruct`'s keyword constructor accepts slots named `t` or after another
  constant, and a slot named after a special variable no longer changes what
  the later slots' initforms see
  ([#693](https://github.com/atgreen/evergreen/pull/693)).

- General arithmetic `LOOP` clauses evaluate bound and step initial forms once
  in source order, before binding the iteration variable, including zero-trip
  loops and loops whose bodies change the original bound or step
  ([#687](https://github.com/atgreen/evergreen/pull/687)).

- The array accessors (`array-rank`, `array-dimensions`, `array-total-size`,
  `array-element-type`, `array-displacement`, `array-has-fill-pointer-p` and
  `adjustable-array-p`) signal a `type-error` for an argument that is not an
  array, instead of answering as if it were a vector, and
  `(upgraded-array-element-type nil)` returns `NIL`
  ([#671](https://github.com/atgreen/evergreen/pull/671)).

- Native x86-64 branches preserve comparison results across intervening boxing,
  fixing incorrect loop counts and results in some unboxed integer loops
  ([#680](https://github.com/atgreen/evergreen/pull/680)).

- `load` and `compile-file` signal `program-error` when called without a file,
  and `load` signals it for an odd keyword list or an unknown keyword (unless
  `:allow-other-keys` is true) instead of loading the file
  ([#672](https://github.com/atgreen/evergreen/pull/672)).

- Private function symbols no longer cause multi-gigabyte allocations in the
  interpreter's arithmetic-classification cache
  ([#662](https://github.com/atgreen/evergreen/pull/662)).

- A variable proclaimed special only by `declaim`, with no `defvar`, is special
  for the rest of a file compiled with `compile-file`, so a `let` of it binds
  dynamically instead of lexically
  ([#675](https://github.com/atgreen/evergreen/pull/675)).

- Fiber migration preserves execution-local state after native calls on s390x,
  preventing wrong `NIL` results and crashes caused by reading a previous
  carrier's fiber identity ([#661](https://github.com/atgreen/evergreen/pull/661)).

- `format`'s `~?` and `~@?` accept a function, such as `formatter` returns, as
  their control as well as a format string
  ([#676](https://github.com/atgreen/evergreen/pull/676)).

- `compile-file` now expands package-local `define-package` macros normally,
  so macros that add `COMMON-LISP` to their package's use list compile and
  load correctly ([#655](https://github.com/atgreen/evergreen/pull/655),
  reported in [#652](https://github.com/atgreen/evergreen/issues/652)).

- `format`'s `~:T` and `~:@T` (`pprint-tab`) produce no output unless
  `*print-pretty*` is true
  ([#677](https://github.com/atgreen/evergreen/pull/677)).

- `egcl-thread:signal-semaphore` no longer gives one permit to two takers.
  An `egcl-thread:try-semaphore` in another thread or fiber could take a
  permit that `signal-semaphore` was about to hand to a waiting fiber; both
  then had it and the semaphore's count went negative
  ([#648](https://github.com/atgreen/evergreen/pull/648)).
- `*print-level*` and `*print-length*` apply to multidimensional arrays, each
  axis counting as a list level, and the `prin1-to-string`/`format ~S` printer
  applies them to vectors as `write-to-string` already did
  ([#681](https://github.com/atgreen/evergreen/pull/681)).

- A fiber's timed wait now has exactly one outcome when its timeout expires
  just as it is woken. Before, `condition-wait` with `:timeout` could return
  true for a fiber whose timeout had already ended the wait, although the
  `condition-notify` that reached it did not count it as notified and went on
  to wake another waiter. A fiber's timed semaphore wait could likewise
  return success while the signalled permit also stayed available, so one
  signal admitted two waiters. A wake that arrives too late for one wait can
  also no longer end the same fiber's next wait, such as a following sleep,
  early ([#647](https://github.com/atgreen/evergreen/pull/647)).
- `subtypep` treats `short-float` as the same type as `single-float` and
  `long-float` as the same as `double-float`, as `typep` already did
  ([#682](https://github.com/atgreen/evergreen/pull/682)).

- A condition is no longer corrupted when a garbage collection runs while it
  is being made. If a slot's initform allocated enough to start a collection,
  `make-condition`, `error` and `signal` could return an object that was no
  longer a condition: `type-of` returned `t`, and `handler-case` for its own
  type did not catch it. `warn` and `error` with format arguments could
  likewise lose their format control string
  ([#645](https://github.com/atgreen/evergreen/pull/645)).
- `format`'s `~E` honors the `@` sign, the overflow character, a width too
  narrow for the optional zero after the point, and a scale factor above 1
  ([#683](https://github.com/atgreen/evergreen/pull/683)).

- An internal error inside compiled code that a native function called no
  longer aborts the process. It is reported as an ordinary Lisp error, as it
  already was for compiled code called from the interpreter. Making a closure
  also no longer fails outright when a garbage collection it starts cannot
  run, for example because another thread did not stop in time; the
  collection is retried at the next allocation
  ([#644](https://github.com/atgreen/evergreen/pull/644); reported in
  [#609](https://github.com/atgreen/evergreen/issues/609)).
- `defstruct` with `(:conc-name "")` interns each accessor in the current
  package, as for any other prefix, instead of using the slot's own symbol
  ([#684](https://github.com/atgreen/evergreen/pull/684)).

- `read-line` on a Gray stream, such as a flexi-streams stream, now reports
  end of file. It returns `eof-value` when `eof-error-p` is false and signals
  `end-of-file` otherwise. Before, it returned an empty string forever, so a
  loop reading lines until `nil` never ended. Building cl-unicode's tables
  from the Unicode data files hung this way ([#643](https://github.com/atgreen/evergreen/pull/643)).
- The reader accepts a bit vector as the contents of `#nA`, and an empty
  level such as `#2a()` gives the axes below it length 0
  ([#685](https://github.com/atgreen/evergreen/pull/685)).

- A closure that has become garbage is now collected even if its body
  contains `progv`, and so is everything it captured. Before, such a closure
  was kept for the rest of the run. bordeaux-threads wraps every thread
  function in one, so each `bt:make-thread` leaked the thread's function and
  its captures: about 54 KB per thread, or 20 KB per connection in a
  thread-per-connection server. `progv` is now compiled. Closures the
  interpreter builds are also freed once they are unreachable, during normal
  garbage collection. Before, they were freed only between files loaded with
  `load` ([#640](https://github.com/atgreen/evergreen/pull/640); reported in
  [#634](https://github.com/atgreen/evergreen/issues/634)).

- A `make-package` nickname that already names a package, a `defpackage`
  `:import-from` of a name its package lacks, and an `import` name conflict
  each signal a correctable `package-error`; `continue` leaves out the
  offending nickname, name or symbol
  ([#692](https://github.com/atgreen/evergreen/pull/692)).
