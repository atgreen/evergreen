The report was generated with five alternating TorCL/SBCL samples on CPU 0,
using a bounded 4 GiB / 300-second child runner and --native-transfer. Every
TorCL sample passed the checksum gate and reported T2 for every listed hot
function before and after timing. POWER-MOD and the exceptional path exercise
native segment entry and landing behavior. Recursive Fibonacci is deliberately
admitted through the established direct-self-call path until a frame-safe
recursive segment entry is implemented (bead bliss-49gcf). Retired instructions
were collected process-wide with perf stat using the cpu_atom/instructions/
event; those counts include startup and compilation and are supplemental to the
in-Lisp throughput timer.

Fibonacci F(30), ten evaluations per workload:
  TorCL median 33 ms (samples 33, 31, 32, 33, 33)
  SBCL  median 57 ms (samples 57, 57, 57, 57, 56)
  TorCL median instructions 7,813,363
  SBCL  median instructions 7,895,858

Ironclad POWER-MOD, 100,000 modular exponentiations:
  TorCL median 533 ms (samples 536, 533, 530, 537, 532)
  SBCL  median  10 ms (samples  10,   9,  11,  10,   9)
  TorCL median instructions 7,814,047
  SBCL  median instructions 7,771,820

Caught conditions, 2,000 calls through HANDLER-CASE repeated 100 times:
  TorCL median 348 ms (samples 347, 348, 348, 346, 348)
  SBCL  median   5 ms (samples   5,   5,   5,   5,   5)
  TorCL median instructions 7,815,642
  SBCL  median instructions 7,739,577

Historical TorCL baseline (commit 2c84d2e1, identical five-sample protocol):
  Fibonacci: 112 ms -> 33 ms (239.4% faster)
  Ironclad POWER-MOD: 508 ms -> 533 ms (4.7% slower)
  Exceptional path: 309 ms -> 348 ms (11.2% slower)

These are local workstation measurements, not universal performance claims.
The HTML and JSON retain the machine, runtime, source, runner, and binary
hashes. The 27-case GC-stress suite remains the correctness evidence for this
milestone.
